# Establish the local CLI and browser boundary

## Scope

Build a local-only Node.js/TypeScript CLI that validates one typed Suno job, opens Suno in bundled Chromium, and keeps all browser session material inside one application-owned runtime directory. This phase will not generate music, call private APIs, attach to an installed browser profile, expose debugging, export storage state, or automate login/challenges.

## Repository state

The repository contains only the empty `.gg/` directory and is not initialized as Git. There are no project conventions or user files to preserve. Implementation will create the minimum npm project without initializing or committing Git.

## Verified references

- Playwright source at `microsoft/playwright@d4e1023f6c03a8dced50eb3db88c2217e7c1a86a`, `docs/src/api/class-browsertype.md:329-352`: `launchPersistentContext` stores cookies/local storage in `userDataDir`, permits only one browser instance per directory, and warns against using Chrome's normal User Data directory.
- The same source, `docs/src/library-js.md:122-179`: the library requires an explicit browser install, explicit cleanup, and `headless: false` for visible operation.
- The same source, `docs/src/api/params.md:1162-1167`: `downloadsPath` confines accepted downloads to a chosen directory.
- Suno's official help article “How do I sign up or log in?”: web authentication starts visibly on `suno.com` and uses user-selected SSO; the CLI must leave this interaction to the user.
- npm registry metadata checked 2026-08-23: Playwright `1.62.1` requires Node `>=20`; TypeScript `7.0.2` and matching Node type definitions are available. Implementation will pin exact compatible versions and commit the generated lockfile only if the user later asks for a commit.

## Design

### Runtime and commands

Create an ESM npm package requiring Node 20 or newer. Use `playwright` as the sole runtime dependency and `typescript` plus `@types/node` for compilation. Avoid a CLI framework: Node's strict `util.parseArgs` covers the small argument surface.

`npm start -- --prompt "..." [--style "..."] [--model "..."] [--instrumental]` will compile and run the CLI. `npm run install-browser` will explicitly install bundled Chromium. `npm test` will compile and run the two exact Node test files without shell glob assumptions.

### Job boundary

`src/job.ts` will define `SunoJob` and `GenerationOptions`, then expose `parseSunoJob(args)` as the only argv boundary. It will require a trimmed, non-empty prompt; accept optional non-empty style/model strings and a boolean instrumental flag; reject unknown flags, duplicate scalar flags, and positional input. Model names remain opaque because Suno's available models can change and this phase does not submit jobs.

The CLI will report only validation status, never echo the prompt, options, argv, page content, URLs with query strings, cookies, JWTs, or arbitrary browser errors.

### Profile and file isolation

`src/runtime-paths.ts` will expose `resolveRuntimePaths(projectRoot)`. It will resolve fixed paths beneath `<project>/.suno-control/`: `browser-profile/` and `downloads/`. A path-containment assertion based on `path.relative` will reject any future path escaping the runtime root, including cross-drive Windows paths. No CLI flag or environment variable can override the profile path.

This deterministic application-owned path makes the operating system's normal Chrome/Edge/Chromium profiles unreachable through the CLI. Tests will prove the profile and downloads are descendants of the runtime root and reject escape paths.

### Browser and authentication boundary

`src/browser.ts` will create the runtime directories and call `chromium.launchPersistentContext(profile, { headless: false, downloadsPath, chromiumSandbox: true })` using Playwright's bundled Chromium. It will not set `executablePath`, `channel`, remote-debugging arguments, `storageState`, stealth behavior, request interception, or direct Suno API calls.

The browser will navigate only to the fixed public `https://suno.com/create` URL. A small visible-page check will treat a Suno sign-in/sign-up route or visible accessible sign-in/sign-up control as login-required. The CLI will instruct the user to authenticate manually in the open browser and press Enter to re-check. If the page still shows login-required or the browser closes, it will return a distinct actionable status without attempting a bypass. Otherwise it will say the browser is ready, wait for Enter, and close the context in `finally`; it will not claim account authentication from absence of a login control.

The visible-UI check is intentionally heuristic because Suno controls its markup. Failure remains safe: the browser stays visible and the CLI performs no privileged action in this phase.

### Secret handling and ignored artifacts

`.gitignore` will exclude `node_modules/`, build output, `.suno-control/`, profiles, downloads, logs, local state, `.env*`, Playwright auth output, storage-state JSON, and log files. `README.md` will state that session cookies naturally remain inside the dedicated persistent profile, that users must never copy/share it, and that deleting the directory logs the automation profile out.

No logging subsystem, storage-state helper, cookie accessor, job persistence, remote-debug server, environment-secret loader, screenshots, traces, or network capture will be added.

## Risks and controls

- Persistent contexts necessarily retain Suno session cookies: confinement to ignored `.suno-control/browser-profile/` is the control; no export/import API will exist.
- Suno markup can change: authentication detection uses only public visible UI and fails without bypassing; README documents manual recovery.
- Two launches cannot share one profile: surface Playwright's profile-in-use condition as an actionable “close the other CLI browser” message.
- External page errors may contain sensitive URLs: map browser failures to fixed local messages instead of printing raw exceptions.
- Dependency install executes third-party package lifecycle behavior: use only verified official packages, exact versions, and a lockfile; browser download remains an explicit command.
