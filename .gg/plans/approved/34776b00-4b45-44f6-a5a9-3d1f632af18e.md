# Automate Suno job submission

## Scope

Implement the bound phase behind the existing parsed CLI job boundary. Keep the dedicated visible persistent Chromium profile and manual authentication flow. Interact only with `https://suno.com/create` through Playwright locators; do not add network interception, storage-state access, browser fingerprint changes, stealth behavior, undocumented endpoints, or challenge solving.

## Current structure

- `src/job.ts` already validates one prompt plus optional style, model, and instrumental values without logging their contents.
- `src/browser.ts` already creates a visible persistent Chromium context in the dedicated `.suno-control/browser-profile` and navigates to Suno Create.
- `src/cli.ts` currently discards the parsed job, handles manual login, then waits only to close the browser.
- `test/cli.test.ts` and `test/job.test.ts` use Node's test runner; CI currently does not install Chromium.
- The attached Playwright source confirms persistent contexts retain session data, permit one instance per profile, and must not use the user's default Chrome profile (`docs/src/api/class-browsertype.md:329-352`). Installed Playwright 1.62.1 documentation also confirms locator actions auto-wait for visibility, actionability, enabled/editable state, and timeout deterministically.

## Design

Add `src/submission.ts` as the single Suno page boundary. It will export a discriminated `SubmissionOutcome` covering `submitted`, `login-required`, `validation-error`, `rate-limited`, and `changed-ui`, plus `submitSunoJob(page, job, waitForChallengeContinue)`. Challenge is an intermediate classified state: the function calls the injected continuation callback, performs no further action until it resolves, then rechecks the page and resumes. Interrupting the callback propagates to existing browser cleanup.

Keep selectors centralized and semantic. Prefer exact `getByRole`, `getByLabel`, and available `getByTestId` locators for the create mode, prompt, style, model, instrumental control, submit button, alerts, login controls, and challenge markers. Confirm the exact current accessible names/test IDs in the visible Suno UI before locking this registry; do not support fields that cannot be confirmed. Custom model options will be selected by exact visible name, and absent/ambiguous controls become `changed-ui` rather than triggering broad CSS or text guesses.

`submitSunoJob` will navigate with `waitUntil: "domcontentloaded"` and bounded navigation/action timeouts, verify the final origin/path before filling, classify login/challenge/error states, enter requested supported values with `fill`, `setChecked`, and exact option clicks, and click Create without `force`, sleeps, artificial typing, mouse simulation, or retries that can duplicate submission. A bounded race among semantic post-submit state locators will map success, validation, rate-limit, login, and challenge states; timeout or locator strictness/actionability failures will fail closed as `changed-ui`. Page-provided error text will not be echoed to the terminal.

`src/cli.ts` will retain the parsed `SunoJob`, pass the active page to the submission boundary, provide the explicit Enter prompt for challenge continuation, print one stable outcome message, assign distinct nonzero exit codes for each failure outcome, and always close the context. Existing manual login remains before submission; challenge handling remains separate and never claims to authenticate the user.

## Tests and verification

Add `test/submission.test.ts` using headless bundled Chromium with `page.setContent` controlled fixture markup—never Suno production. Cover semantic filling and one submit click; omitted optional fields; exact model selection; logged-out, validation, rate-limit, and changed-UI outcomes; challenge inactivity until callback resolution; successful resume after explicit continuation; wrong-origin refusal; and no duplicate click after an ambiguous timeout. Add focused CLI tests for job forwarding, messages/exit codes, challenge prompt wiring, and context cleanup.

Update `package.json` so `npm test` includes the submission suite, and update CI to install Chromium with Playwright's documented installer before tests. Update `README.md` with the actual submission behavior, supported confirmed fields, stable outcomes, challenge continuation, and unchanged profile/privacy constraints. Preserve existing no-secret/static checks and extend them to reject request routing/interception, private Suno API strings, `force`, `waitForTimeout`, stealth/fingerprint settings, and simulated-human input.

## Risks

- Suno's accessible names and controls can change; central selectors and explicit `changed-ui` classification contain that failure without unsafe fallback selectors.
- A post-click timeout cannot prove whether Suno accepted a job; the implementation must not retry submission automatically, preventing duplicate generations.
- CAPTCHA providers may use cross-origin frames; detection may identify only the visible challenge container/frame and must always hand control to the user.
- Browser-backed fixture tests add a Chromium install to CI; no new runtime dependency is required because Playwright is already pinned.
