# Repair outgoing regressions

## Objective

Repair the four confirmed regressions in `origin/main...HEAD` with the smallest cohesive diff, while preserving fail-closed assisted preparation, diagnostic redaction, non-submitting smoke behavior, durable no-resubmission guarantees, and all five approved completion-tracking criterion commands.

## Findings and intended fixes

### 1. Application boundary and diagnostics

The approved architecture says `src/application/run-jobs.ts` may depend only on domain values, application contracts, and generic queue logic. It currently imports `RuntimePaths`/`resolveJobPaths` from `src/config.ts` and concrete diagnostic construction/writing from `src/suno/diagnostics.ts`. The current architecture test does not reject this direction.

Use a narrow application-owned diagnostic contract rather than moving Suno/filesystem details into orchestration:

- Add an `OutcomeDiagnosticWriter` contract to `src/application/contracts.ts` with one asynchronous operation accepting the validated job identifier and semantic `AutomationOutcome`.
- Replace `RunJobsDependencies.paths` in `src/application/run-jobs.ts` with that contract. Keep the existing best-effort `try/catch`, but delegate construction, category mapping, path resolution, containment, and writing.
- Add the concrete adapter function in `src/suno/diagnostics.ts`, reusing `resolveJobPaths`, `createOutcomeDiagnostic`, `mapDiagnosticCategory`, and `writeDiagnostic`; do not duplicate redaction or file-writing logic.
- Wire the concrete writer only in `src/main.ts`, the existing composition root.
- Update `test/run-jobs.test.ts` to inject no-op, real local, and throwing writers as appropriate. Keep the real diagnostic serialization assertions and the rule that writer failure cannot replace the original result.
- Extend `test/architecture.test.mjs` so application modules reject imports from `src/config.ts` and `src/suno/`, closing the exact gap without broad new architecture machinery.

### 2. Stale phase verification entry points

`package.json` still exposes `test:phase-command`, `test:phase-profile`, `test:phase-ignores`, `test:phase-secrets`, and `test:phase-login`, but `test/phase-completion.test.mjs` references deleted compiled modules, the former browser return shape, the former profile directory, and obsolete output wording.

Keep the five public scripts unchanged and port their shared test file:

- Import `launchSunoBrowser` from `dist/src/suno/browser.js` and `resolveRuntimePaths` from `dist/src/config.js`.
- Spawn `dist/src/main.js`, retaining argument-array spawning, a fresh temporary working directory/profile, the timeout, prompt-redaction assertion, and cleanup.
- Adapt the profile test to `{ context }`, `.suno-control/chrome-profile`, and `src/suno/browser.ts`.
- Match the current root-only `/downloads/` ignore entry.
- Scan the current source entry points for prohibited credential/session/private-API surfaces. Remove only the obsolete prohibition on Playwright's pinned `channel: "chrome"`, which selects the supported visible browser and is not browser-identity manipulation.
- Assert current stable queue/login output rather than deleted `Job validated` prose, while preserving exit code `3` and no prompt disclosure.

These commands remain outside the default test runner because two intentionally launch a visible, fresh-profile browser; the fresh profile keeps them non-submitting.

### 3. Smoke challenge continuation

Before the refactor, live smoke invoked the supplied manual challenge continuation. `src/suno/inspection.ts` now accepts but never calls it, while `README.md` still promises a pause and `test/submission.test.ts` explicitly locks in the regression.

Restore the documented behavior without reintroducing form filling:

- In `runLiveSmoke`, classify the initial page state, call `waitForChallengeContinue` exactly once only when a challenge is visible, then reclassify the page.
- Keep `submitted: false`, `creditsConsumed: false`, no form-control writes, no Create click, and the existing dependency-graph prohibition against reaching submission.
- Return `ready`, `login-required`, `challenge-required`, or `changed-ui` from the post-pause state; set `challengePaused` only when the callback was actually invoked.
- Remove the unused `SunoJob` parameter and `SMOKE_JOB` constant from `src/suno/inspection.ts` and `src/smoke-cli.ts` rather than retaining dead compatibility code.
- Update the existing challenge fixture in `test/submission.test.ts` to require one callback, successful post-challenge reclassification, empty fields, and zero submissions. Keep the unresolved-challenge path fail-closed if needed by the same fixture.

### 4. Login/challenge observation mapping

`CompletionObservation` correctly carries `login-required` versus `challenge-required` in `error.code`, and `AutomationStatus` has distinct statuses and exits. `src/suno/playwright-adapter.ts` currently collapses every blocked observation to `challenge-required`, causing observed login to return exit `9` instead of login exit `3`.

Preserve the existing bounded observation contract and make the discriminator type-safe:

- Split the blocked `CompletionObservation` variant in `src/suno/completion.ts` so its code is the literal union `login-required | challenge-required`; keep persisted checkpoint status `blocked` unchanged.
- Map a blocked observation in `src/suno/playwright-adapter.ts` from that narrowed code instead of hard-coding `challenge-required`.
- Extend `test/completion.test.ts` with both login and challenge fixtures asserting the distinct fixed codes. Add or extend the application contract test in `test/run-jobs.test.ts` to prove `login-required` yields exit `3`/login category and `challenge-required` remains exit `9`/challenge category.

## Scope controls

- Do not change `src/suno/assistance.ts`, `src/suno/form-controls.ts`, assisted fixtures, Create-click guards, completion retry limits, persistence transitions, output naming, or download behavior.
- Do not add dependencies, compatibility wrappers, generated files, or new command aliases.
- Keep diagnostics bounded, redacted, path-contained, atomic, restrictive, and best-effort.
- Keep live smoke and the repaired phase checks non-submitting; never use an authenticated runtime profile for the fresh-profile phase tests.

## Verification criteria

- `test/architecture.test.mjs` rejects the former application-to-config/Suno imports and still proves smoke cannot reach submission.
- Diagnostic tests exercise the injected contract through the real concrete writer and preserve original outcomes when writing fails.
- Smoke challenge fixtures call the manual continuation exactly once, reclassify afterward, leave every form field empty, and never click Create.
- Login and challenge observation fixtures produce distinct automation statuses, exit codes, categories, and fixed diagnostic codes.
- The five legacy `test:phase-*` scripts resolve current files and pass separately after one build.
- `npm test` and `npm run build` pass separately.
- The five approved bounded completion-tracking commands pass separately and in order:
  1. `npm test -- --criterion=1`
  2. `npm test --silent -- --criterion=2`
  3. `npm run test -- --criterion=3`
  4. `npm test -- --criterion=4`
  5. `npm test --silent -- --criterion=5`

## Risks

- The phase command/login checks launch visible Chrome. Their temporary working directory must remain the source of runtime paths so they cannot reuse an authenticated profile or submit work.
- Moving diagnostic orchestration behind a contract can accidentally skip diagnostics. Real-writer tests must still assert exact stage, category, selector facts, and redaction.
- Challenge continuation can hang if a person never continues. Keep the existing bounded Playwright waits and test only controlled fixture continuation; do not automate challenge completion.
- Do not broaden status strings: persisted job status remains `blocked`; only the semantic automation outcome distinguishes login from challenge.
